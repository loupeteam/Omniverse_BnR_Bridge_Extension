Changelog

[0.3.0-rc1]
See MIGRATION.md for upgrading from 0.1.0.
- The extension is now a thin driver for the vendor-neutral PLC bridge framework `loupe.simulation.bridge` (Omni-Utils), which it depends on (`0.3.x`). On startup it registers `br_bridge.BrDriver` under the driver name `br` with the options `Host` and `Port`; the framework owns the PLC prims, the window, the Python API, the message bus and the USD mirror. A stage can mix B&R and Beckhoff PLCs under one system.
- PLC prims use the neutral schema: `bridge:driver = "br"`, `br:Host`, `br:Port`, `bridge:Enable`, `bridge:RefreshRate`, `bridge:Variables` (a `string[]`), `bridge:MirrorToUsd`, `bridge:MirrorSymbols`. Prims with the `br_bridge:*` attributes of the earlier 0.3.0 preview still load, with a deprecation warning.
- **Deprecated:** `loupe.simulation.br_bridge.BrBridge`. It warns at import and re-exports the framework's `Manager`, `get_system` and the `EVENT_TYPE_*` constants on the vendor bus names `loupe.simulation.br_bridge.<KIND>.<plc>`, which the framework pushes and accepts next to the neutral `loupe.simulation.bridge.<KIND>.<plc>` while its `legacyBusNames` setting is on (default on in 0.3, off in 0.4). The module is removed in 0.5. Import from `loupe.simulation.bridge` instead.
- **Deprecated:** calling `Manager()` with no name (the 0.1.0 form). It still works: it addresses `PLC1` and, if no `/PLC/PLC1` prim is loaded, creates that runtime in memory from the 0.1.0 persistent settings (`PLC_IP_ADDRESS`, `PLC_PORT`, `REFRESH_RATE`, `ENABLE_COMMUNICATION`) with a warning. Nothing is written to the stage file; when a framework rescan (stage open, the window's Refresh, a driver registered) drops it, it is re-created with the settings it last had. Removed in 0.4.0. `BrBridge.Manager` accepts the PLC name positionally, as `Name=` or as `name=`.
- The extension's own `Runtime`, window (`ui_builder.py`) and `global_variables.py` are gone, and so is the Omni-Utils submodule at `loupe/simulation/common` (and `.gitmodules`). Code that imported `loupe.simulation.common` or those modules imports from `loupe.simulation.bridge`.
- The driver and the shared runtime are pip requirements (`websockets`, `br-bridge`; `plc-bridge` comes with the framework) installed by Kit's pipapi. Until they are on PyPI the wheels ship in the extension's `wheels/` folder, filled by `tools/build_wheels.py`, which adds pure-Python websockets wheels so the folder installs on any platform and on Python 3.10.
- Multiple PLCs, each a prim under `/PLC/`, so connection settings are saved in the stage instead of in persistent app settings.
- The values read from the PLC are mirrored into the stage as prims in the session layer, with `write:*` attributes for writing back. Array elements are mirrored as `_<index>` child prims. Switch it off per PLC with `bridge:MirrorToUsd = false`, or limit it with `bridge:MirrorSymbols`. Write-back keeps the OMJSON spelling (`TestProg:lreal`).
- The runtimes are created at startup and on stage open/close, so the bridge works without opening the window (headless).
- The OMJSON websocket driver moved out of the extension into the plain-Python `br_bridge` package at the repo root, with no Omniverse dependency and its own pytest suite. `websockets_driver.py` is gone; its parser is the shared `plc_bridge.nest_symbol` with the driver's separators `":."`, and its tests moved to `br_bridge/tests/test_symbols_legacy.py`.
- The polling is the plain-Python `plc_bridge.PlcRuntime`: one daemon worker per PLC with a bounded join, each scan flushing the queued writes and then reading; a queued write wakes the loop.
- A symbol the PLC does not know (OMJSON returns `"undefined"`) or leaves out of its reply is no longer delivered as data; it is reported in the status as `Error Reading: <symbol>: <reason>` and `Reading OK` when it recovers. A write the PLC rejects is reported as `Error Writing: <symbol>: <reason>`. Every request is bounded by the driver's timeout (3 s) and a lost websocket reports `Disconnected` and reconnects by itself.
- Menu entry moved from `B&R Bridge / Open Bridge Settings` to the framework's `Loupe / PLC Bridge`; the window shows one PLC at a time with `Write To USD` / `Update From USD` instead of `Save` / `Load`. The `Dev Tools` section is gone.
- Headless check harness under `tools/kit_check` (a 0.3.0rc1 prim and a neutral prim, a 0.1.0 script with and without a PLC name, live against the mock OMJSON server) and `tools/kit_test.ps1` for the Kit tests.
